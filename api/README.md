# Management API contract

`management.openapi.json` is a reviewed OpenAPI 3.0.3 subset used to generate the internal HTTP client and models. The initial seven operations cover FOCUS push lifecycle and discovery. The expanded subset adds tenant administration, AWS and Google Cloud connection management, Azure service-principal exports, AI gateway settings, Kubernetes registrations, and virtual-tag configurations.

The source baseline is backend commit `923e81f496bb1be4fa5e064afce746d0c19ae755`. The new `GetIntegrationConnection` operation is supplied by the separate `feat/terraform-integration-contract` backend change. Stable operation identifiers for the other integration operations come from that change too. The read contract and stable identifiers are committed in backend `fe88f2994d819e1ebb131b1f723766f48fff697a`. At SDK creation, the backend change was not deployed.

The full Swagger artifact generated from that backend checkout with its pinned `swag` v1.16.6 has SHA256 `487a650ffcb4d01de620c31586131d7067481ee0604efcae7fdbbd09ef7d11e7`. It is supporting research evidence, not a build input. The relevant source files are `controllers/integrations/integrations.go`, `controllers/integrations/registry.go`, `internal/user/user.go`, `responses/success.go`, and `responses/error.go` in the backend repository.

The reviewed differences from the full Swagger representation are deliberate.

- `/api/v1/me` has a session/API-key union in the full API description. This SDK authenticates with an API key, so its `Identity` schema follows `user.CurrentAPIKeyResponse`, including optional organization metadata and permission scopes.
- The list route's session-oriented tenant header is not required here. API-key authentication establishes the authorized tenant, and this client does not support session authentication.
- Connection models retain the common identity, provider, tenant, display name, status, ingestion mode, and timestamp fields. Telemetry, billing history, recommendation, and sandbox details are outside this SDK slice. The server can return those extra fields without changing this model.
- Required and nullable fields follow the Go JSON response and handler behavior. String IDs stay strings; `id` is an internal UUID and `connection_id` is the public `fpc_` identifier.
- FOCUS push creation requires a billing-account identifier. Provider, display name, and tenant are optional. The key's tenant is the default; omitting the provider allows the first billing push to set it.
- Rename and disconnect return success envelopes without a data payload. The facade also handles `204 No Content` without attempting JSON decoding.
- Error response schemas document the API shape, but the public facade exposes only the HTTP status and operation name. Arbitrary server text and raw bodies are not diagnostics.

The expanded management subset follows the reviewed code on the backend `feat/terraform-management-api` change. Its tenant contract has explicit organization and tenant UUID path parameters and requires an organization owner with `organization:manage`. The AWS and Google Cloud request schemas deliberately omit long-lived credentials. AWS role and GCP impersonation update objects retain optional nested pointers, while AI gateway update maps distinguish omission from an explicit empty map. Cloud settings expose no secret material. The model-search operation reads canonical keys, display names, and publishers from the existing gateway model catalog endpoint; it returns at most twenty matches, not the whole catalog.

Run `make generate` to regenerate with oapi-codegen v2.9.0. Run `make check-generated` to verify the committed client matches this snapshot. Neither command downloads the live CostGraph schema.

The Azure subset follows backend commit `7996f053` on `feat/azure-provider-v02`, based on `40ad91a89ef621d1ff391feb46c75a4bf9c78ddc`. It connects an existing service-principal FOCUS export, reads nonsecret settings, and updates the same connection UUID. The create and update requests accept a write-only client secret. A nonsecret secret_version counter survives refresh and import; a rotation must increase it. Settings responses never include the secret. Legacy directly owned Azure connections report version 0 until rotated. Credential-source reuse and incompatible account identities return a conflict. The backend checks real export access before saving. Positive Azure lifecycle coverage awaits an isolated cloud account.

Kubernetes registration management follows backend commits `4c08f634d8245b0daefbe00be2f46388da89e032` and `d8706cfa38c9ccb6f4e9764ce057cbc6c93c96e5`. It adds owner-scoped create, read, and disconnect operations under `/api/v1/organizations/{org_id}/kubernetes-clusters`. This management contract returns the registration UUID, name, and tenant. Collector reporting remains a separate, tenant-bound API. Create refuses an active name collision with HTTP 409. Disconnected registrations read as HTTP 404 with machine code `not_found`, retain history, and require explicit owner re-enrollment before a collector may register that name again. Re-enrollment assigns a fresh UUID. Availability requires deployment of that backend change.

The virtual-tag subset follows backend `91bcfa78` in `controllers/virtual_tag_configurations.go` and `internal/virtualtag/management.go`. It manages one key and its complete ordered rules atomically. Every operation takes an explicit tenant header, authorized by tenant-bound `virtual-tags:read` or `virtual-tags:write` scopes. Updates and deletes require the aggregate revision, which covers metadata and rules. A conflict is returned without retry. Legacy rules expose their existing UUID as `rule_key` until edited. List pagination returns metadata only. `APIError.Code` exposes only a fixed list of machine codes, including authoritative `not_found`; arbitrary server messages remain excluded.
